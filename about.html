CÂU HỎI 1

Khác biệt giữa Position: Absolute vs Relative, Ứng dụng Responsive & Ảnh hưởng khi Deploy

1. So sánh bản chất Absolute vs Relative

Trong CSS, thuộc tính position kiểm soát cách một phần tử được đặt vị trí trên trang:

Tiêu chí position: relative position: absolute
Luồng tài liệu (Normal Flow) Vẫn nằm trong luồng. Không gian ban đầu của phần tử vẫn được giữ nguyên như trước khi dịch chuyển. Bị rút hoàn toàn khỏi luồng văn bản (taken out of flow). Các phần tử khác sẽ chiếm lấy vị trí trống đó.
Gốc tọa độ tham chiếu (top/right/bottom/left) Tham chiếu theo chính vị trí ban đầu của nó trong luồng tài liệu. Tham chiếu theo phần tử tổ tiên gần nhất có position khác static (thường là relative). Nếu không có, nó tham chiếu theo <body> hoặc viewport.
Tác động tới phần tử xung quanh Chỉ thay đổi vị trí thị giác của chính nó, không đẩy hay kéo các thẻ lân cận. Không chiếm không gian vật lý, dễ đè lên hoặc bị đè bởi các thẻ khác (quản lý qua z-index).

2. Ví dụ thực tế trong thiết kế Responsive: Notification Badge

Kỹ thuật kinh điển là kết hợp relative ở thẻ cha làm mốc tọa độ và absolute ở thẻ con để định vị huy hiệu thông báo góc trên bên phải: 

/* Thẻ cha: Container icon chuông thông báo */
.notification-bell {
  position: relative; /* Đặt làm mốc tọa độ cho con */
  display: inline-block;
  width: 48px;
  height: 48px;
}

/* Thẻ con: Huy hiệu số thông báo đỏ */
.badge-count {
  position: absolute;
  top: -6px;
  right: -6px;
  background-color: #ef4444;
  color: #ffffff;
  font-size: 11px;
  font-weight: bold;
  border-radius: 9999px;
  padding: 2px 6px;
  /* Đảm bảo badge luôn neo chặt vào góc thẻ cha trên mọi độ phân giải màn hình */
}

3. Ảnh hưởng và các rủi ro khi Deploy thực tế

  • Lỗi "Mất mốc tọa độ" (Missing Relative Parent): Nếu quên không đặt position: relative cho phần tử cha, thẻ absolute sẽ vô tình bám theo <html>. Khi deploy và mở trên các màn hình có tỉ lệ khác (ultrawide, tablet, mobile), phần tử sẽ văng ra ngoài khung hình.
  • Nguy cơ che đè nội dung (Overlap Glitch): Vì absolute không chiếm chỗ, chiều cao của thẻ cha có thể bị sụt về 0px nếu chỉ chứa các con absolute. Các thành phần bên dưới sẽ trồi lên đè vào nhau.
  • Giải pháp chuẩn Responsive: Ưu tiên dùng Flexbox / CSS Grid cho toàn bộ layout xương sống (page structure). Chỉ sử dụng absolute cho các chi tiết trang trí cục bộ (badge, tooltip, nút đóng modal, icon overlay) khi đã bọc bên trong một container relative.
CÂU HỎI 2

Quy trình Đăng ký Domain, Hosting, DNS, Đề xuất Triển khai & Rủi ro Bảo mật

1. Ba bước chuẩn để đưa một Website lên Internet

  1. Đăng ký Domain (Tên miền): Mua định danh địa chỉ web (ví dụ: mssv-portfolio.com) từ các nhà đăng ký được ICANN công nhận (như Namecheap, GoDaddy, Mắt Bão, PA Việt Nam).
  2. Thuê Hosting / Máy chủ Web: Thuê không gian lưu trữ trực tuyến hoạt động 24/7 để chứa mã nguồn (HTML, CSS, JS, hình ảnh, cơ sở dữ liệu) và chạy phần mềm web server (Nginx, Apache hoặc Static CDN).
  3. Cấu hình DNS (Hệ thống phân giải tên miền):
    • Tạo bản ghi A Record: Trỏ tên miền trực tiếp tới địa chỉ IPv4 của Hosting (ví dụ: @ → 192.0.2.1).
    • Tạo bản ghi CNAME Record: Định tuyến tên miền phụ (subdomain) sang tên miền chính hoặc máy chủ dịch vụ (ví dụ: www → yourusername.github.io).

2. Đề xuất nền tảng miễn phí phù hợp nhất cho sinh viên: GitHub Pages & Netlify

GitHub Pages

• Hoàn toàn miễn phí, tích hợp sẵn với Git Repository.
• Tự động kích hoạt chứng chỉ SSL/HTTPS miễn phí.
• Cực kỳ tối ưu cho các dự án tĩnh (HTML/CSS/JS thuần, đồ án học phần).
• Domain mặc định: username.github.io/repo-name/.

Netlify / Vercel

• Hỗ trợ CI/CD tự động: Commit code lên GitHub là tự động Build & Deploy.
• Cung cấp Deploy Previews cho từng Pull Request.
• Mạng lưới CDN toàn cầu với tốc độ truy xuất cực nhanh.
• Quản lý biến môi trường (Environment Variables) an toàn.

3. Rủi ro an ninh mạng cần phòng tránh

  • Thiếu mã hóa SSL/HTTPS: Nếu website chạy trên giao thức HTTP cũ (cổng 80), mọi dữ liệu truyền giữa client và server (mật khẩu, form dữ liệu) đều ở dạng plain text, dễ bị tấn công nghe lén (Man-in-the-Middle - MitM). Cần luôn bật tính năng Enforce HTTPS.
  • Lộ lọt thông tin nhạy cảm lên Git: Tuyệt đối không commit các file chứa API Key bí mật, mật khẩu cơ sở dữ liệu hoặc thông tin người dùng vào public repository. Luôn dùng file .gitignore.
  • Nguy cơ Subdomain Takeover: Xảy ra khi bản ghi DNS CNAME vẫn trỏ tới một hosting hoặc bucket đã bị xóa hoặc ngưng gia hạn, cho phép kẻ tấn công đăng ký lại dịch vụ đó để chiếm quyền điều khiển tên miền.
CÂU HỎI 3

So Sánh LET, CONST, VAR (Scope, Hoisting), Ví Dụ Lỗi Điển Hình & Kỹ Thuật Debug Bằng Chrome DevTools

1. Bảng so sánh toàn diện: Scope, Hoisting & Re-assignment

Từ khóa Phạm vi (Scope) Cơ chế Hoisting Tái khai báo & Gán lại
var Function Scope (hoặc Global nếu khai báo ngoài hàm). Bỏ qua khối lệnh {} như if, for. Được hoisted lên đầu scope và khởi tạo giá trị mặc định là undefined. Truy cập trước khi khai báo không bị crash code. Cho phép khai báo lại nhiều lần trong cùng scope; cho phép gán lại giá trị.
let Block Scope (chỉ tồn tại bên trong cặp ngoặc nhọn { ... }). Được hoisted nhưng nằm trong vùng chết tạm thời Temporal Dead Zone (TDZ). Truy cập trước khi khai báo sẽ ném lỗi ReferenceError. Không cho phép khai báo lại trong cùng scope; cho phép gán lại giá trị.
const Block Scope (chỉ tồn tại bên trong cặp ngoặc nhọn { ... }). Tương tự let, nằm trong Temporal Dead Zone (TDZ) trước khi tới dòng code khai báo. Không cho phép khai báo lại; không cho phép gán lại tham chiếu (nhưng các thuộc tính của Object/Array vẫn mutate được). Bắt buộc phải gán giá trị khi khởi tạo.

2. Ví dụ lỗi logic kinh điển: Closure trong vòng lặp bất đồng bộ

Đoạn code dưới đây minh họa sai lầm rất phổ biến khi dùng var và cách khắc phục triệt để bằng let: 

// ❌ LỖI LOGIC VỚI VAR:
for (var i = 1; i <= 3; i++) {
  setTimeout(() => {
    console.log("var i:", i);
  }, 100);
}
// KẾT QUẢ IN RA: 4, 4, 4
// Giải thích: Do 'var' có function scope, biến 'i' bị chia sẻ chung. Khi timer chạy xong,
// vòng lặp đã kết thúc và i đã đạt giá trị 4.

// ✅ KHẮC PHỤC HOÀN TOÀN BẰNG LET:
for (let j = 1; j <= 3; j++) {
  setTimeout(() => {
    console.log("let j:", j);
  }, 100);
}
// KẾT QUẢ IN RA: 1, 2, 3
// Giải thích: 'let' có block scope, mỗi vòng lặp tạo ra một phạm vi mới lưu giữ giá trị j độc lập.

3. Quy trình từng bước Debug bằng Chrome DevTools

  1. Mở công cụ DevTools: Bấm phím F12 (hoặc tổ hợp Ctrl + Shift + I trên Windows), chọn tab Sources.
  2. Đặt Breakpoint (Điểm ngắt): Điều hướng cây thư mục bên trái để mở file script cần kiểm tra. Nhấn chuột vào số dòng code (Line Number) muốn dừng thực thi để đặt Breakpoint màu xanh.
  3. Kích hoạt thực thi: Thao tác trên giao diện web (click nút, submit form, gõ phím) để trình duyệt chạy code đến dòng breakpoint và tạm dừng chương trình.
  4. Quan sát bảng điều khiển Scope: Nhìn sang cột phải tab Scope để kiểm tra giá trị của các biến trong:
    • Local Scope: Biến bên trong hàm đang chạy.
    • Block Scope: Biến khai báo bằng let/const trong khối hiện tại.
    • Global Scope: Biến toàn cục (đối tượng window).
  5. Điều khiển từng bước lệnh:
    • F10 (Step over): Thực thi sang dòng lệnh kế tiếp.
    • F11 (Step into): Đi sâu vào bên trong thân hàm được gọi.
    • Shift + F11 (Step out): Thực thi hết hàm hiện tại và quay về hàm cha.
  6. Theo dõi linh hoạt với Watch & Console: Thêm các biểu thức cần kiểm tra vào tab Watch hoặc gõ lệnh trực tiếp vào tab Console dưới đáy để kiểm tra giá trị thời gian thực mà không cần dùng console.log thủ công.
CÂU HỎI 4

Cơ Chế Event Delegation (Ủy Quyền Sự Kiện), Ví Dụ Danh Sách Động & Phân Tích Lợi Ích Tối Ưu

1. Nguyên lý vận hành: Dựa trên Event Bubbling (Nổi bọt sự kiện)

Khi một sự kiện xảy ra trên một phần tử DOM (ví dụ: click vào thẻ <button>), sự kiện đó không dừng lại tại chỗ mà sẽ lan truyền ngược lên các phần tử cha tổ tiên: button → li → ul → main → body → document → window. Hiện tượng này gọi là Event Bubbling.

Event Delegation là kỹ thuật tận dụng sự nổi bọt: Thay vì gắn hàng trăm Event Listener lên từng phần tử con, ta chỉ cần gắn một Event Listener duy nhất lên phần tử cha chung, rồi sử dụng thuộc tính e.target hoặc hàm e.target.closest() để xác định chính xác phần tử con nào đã phát sinh sự kiện.

2. Minh họa Code thực tế: Quản lý Danh sách động (Thêm / Xóa Item)

// HTML cấu trúc danh sách cha:
// <ul id="esports-roster">
//   <li data-id="1">Bâng <button class="btn-kick">Xóa</button></li>
// </ul>

const rosterList = document.getElementById('esports-roster');

// ✅ ÁP DỤNG EVENT DELEGATION: Chỉ gắn 1 listener duy nhất trên thẻ cha <ul>
rosterList.addEventListener('click', function(event) {
  // Tìm nút bấm xóa gần nhất được click
  const kickBtn = event.target.closest('.btn-kick');
  
  if (kickBtn) {
    // Tìm phần tử li tương ứng để xóa
    const memberItem = kickBtn.closest('li');
    if (memberItem) {
      console.log('Đã xóa thành viên:', memberItem.dataset.id);
      memberItem.remove();
    }
  }
});

// Khi thêm phần tử mới bằng JS:
// rosterList.insertAdjacentHTML('beforeend', '<li data-id="2">Fish <button class="btn-kick">Xóa</button></li>');
// => Nút 'Xóa' của Fish TỰ ĐỘNG hoạt động mà KHÔNG CẦN addEventListener lại!
